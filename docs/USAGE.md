# 使用教学：从建群到跑完一个任务

面向第一次使用的人。假设你已经按 [FEISHU-SETUP.md](FEISHU-SETUP.md) 在飞书开放平台
建好自建应用、拿到了 App ID / App Secret，并且已经用 `install` / `install.sh` 装好桥、
`start` / `start.sh` 把健康检查跑成 `ok: true`。

## 核心模型：一个飞书话题 = 一个 Codex 任务

普通消息流里，一个"话题"（topic）就是一条根消息底下挂的所有回复。桥把这个结构直接
映射成 Codex 的任务单元：

- 同一个话题里的消息**按先后顺序排队**，一条一条交给 Codex 执行；
- 不同话题**并行**执行，互不排队；
- 话题里每一轮的最终回答、执行进度卡片、图片和文件产物，都**回复在这个话题下**，
  不会跑到群里的别处。

所以"开一个新任务"= "开一个新话题"，"接着上一轮继续"= "在同一个话题里再发一条"。

## 前提：用的是「话题形式群」

桥依赖飞书的话题结构。请确认群是**话题形式**的：

群设置 → 「群模式」/「话题」→ 选择**话题形式**（而不是普通聊天流）。

普通群不是不能用，但一话题=一任务的映射会退化成"整群一个消息流"，多任务并行时
回答会混在一起，不推荐。

把机器人拉进群之后：

- 如果应用拿到了敏感权限 `im:message.group_msg`（能收群里全部消息），直接说话即可；
- 没拿到的话，飞书只会把 **@机器人** 的消息推给桥。需要逐条 @ 时，把
  `config.json` 里的 `feishu.require_mention_in_group` 设为 `true` 让行为显式化。

## 第一步：配对

桥默认只处理白名单里的会话，配对就是把某个飞书会话登记进来。

1. 在电脑上取配对码：

   ```powershell
   .\windows\pair-code.ps1        # Windows
   ./macos/pair-code.sh           # macOS
   ```

2. 在飞书里把配对码发出去：在群里 `@机器人 /bind <配对码>`，或直接和机器人私聊
   `/bind <配对码>`。

配对成功后桥会回一条确认。这一步只需要做一次。（也可以跳过配对，直接在
`config.json` 的 `feishu.allowlist.open_ids` / `chat_ids` 里写死你的 open_id 或群 id。）

## 第二步：开第一个任务

在群里发：

```
@机器人 codex 看一下 src 下面的代码结构，给我一份模块清单
```

其中 `codex` 是**项目别名**，对应 `config.json` 里 `projects` 的某个目录：

```json
{ "projects": { "codex": "D:\\Codex\\my-project" } }
```

桥会做四件事：自动开一个新话题、在里面建一条任务、拉起 Codex 执行、把过程和结果
回复到该话题。之后**不需要再 @机器人**，直接在那个话题里继续发消息就行。

想加更多目录就改 `projects`；`quick_start.project_keywords` 可以给项目配关键词，
让「@机器人 修一下 FitTrack 的登录」这种模糊说法也能命中正确的项目。

## 第三步：日常怎么用

- **接着聊**：在话题里直接发消息，按 FIFO 排队执行。
- **看进度**：任务跑得久时会自动出现进度卡片；也可以发 `/progress` 立刻拉一张，
  这条不占队列。
- **叫停**：发 `/stop`，或点进度卡片上的「中断当前处理」。
- **换模型**：发 `/model`，选中后记住，之后这个会话都用它；随时可以改。
- **多任务**：想并行处理别的事，就在群里再开一个新话题。

## 指令速查

| 指令 | 作用 |
| --- | --- |
| `/bind <配对码>` | 把当前会话与桥配对 |
| `/projects` | 查看可用项目别名 |
| `/new [项目] [任务内容]` | 新建任务并绑定当前话题 |
| `/tasks [关键词]` | 搜索最近的任务 |
| `/use <任务 ID 前缀>` | 把当前话题切到某个任务 |
| `/resume [任务 ID 前缀]` | 绑定到已有任务；不带参数时列出最近任务 |
| `/status` | 当前话题的任务与队列 |
| `/progress` | 立即查看执行进度（不占用队列） |
| `/where` | 当前话题的路由与模型设置 |
| `/models` | 列出可用模型 |
| `/model <模型> [强度]` | 设置模型与推理强度 |
| `/compact` | 压缩当前任务上下文 |
| `/renew` | 压缩后继承历史开一个新任务 |
| `/fork` | 分叉当前任务 |
| `/clear` | 在当前话题里开一个空白任务 |
| `/rename [新标题]` | 修改当前话题标题 |
| `/upload_revoke` | 撤销持续上传授权 |
| `/stop` | 中断当前正在执行的处理 |
| `/cancel` | 取消进行中的交互选择 |
| `/help` | 帮助 |

## 图片、文件与产物

- **发给机器人**：直接往话题里发图片或文件即可作为输入；图文混排也支持，桥会把
  图片和文字一起交给 Codex。
- **机器人回传**：Codex 在任务里产出的图片/文件会**自动回传**到同一个话题。
  回传有白名单：只有 `artifact_roots`、当前项目目录、桥自己的 `artifacts/`
  下的文件会被上传。产物写到项目目录里最稳妥。

## 任务生命周期

```
你发消息 → 桥落 SQLite → 排队 → 取租约 → turn/start
   → 执行中的进程/进度写库 → 进度卡片刷新
   → 最终回答、产物、表情回执 → 一条条投递回话题
```

桥在这里的耐久性做了保证：

- **重启不丢事**：进程被杀/机器重启后，正在跑的 turn 会被标记中断并重新排队，
  队列自动续跑，未投递的消息按指数退避重试。
- **重推不重复执行**：飞书重推同一个事件时靠 `event_id` 去重。
- **崩溃自愈**：桥挂了会被自启机制在两分钟内重新拉起（只在 Codex 桌面端开着的时候）。

## 常见问题

| 现象 | 怎么办 |
| --- | --- |
| 发了消息没反应 | 确认桥在跑（`status.ps1` / `status.sh` 返回 `ok: true`）；确认话题所在群是话题形式；没拿到群消息权限时记得 @机器人 |
| 回「这条消息里没有可处理的内容」 | 消息里既没有文字也没有图片/文件 |
| 回「未配对」 | 先做 `/bind`，或把自己的 open_id 加进 `feishu.allowlist.open_ids` |
| 图片/文件没回传 | 产物是否落在项目目录、`artifact_roots` 或桥的 `artifacts/` 下 |
| 想换端口 | 改 `config.json` 的 `health_port`，然后重启桥 |
| 想看现场日志 | 应用目录下的 `bridge.log`（Windows 默认 `%LOCALAPPDATA%\CodexFeishuBridge`，macOS 默认 `~/Library/Application Support/CodexFeishuBridge`） |

## 安全边界（务必知道）

首版按**无人值守**运行：`approval_policy = "never"` + 沙箱 `dangerFullAccess`。
也就是说，能驱动这个机器人的人，等于能在你机器上跑命令、改文件。

- 只把桥配给可信的会话；`feishu.allowlist` 是你的第一道门。
- App Secret 存在系统凭据库（Windows DPAPI / macOS 钥匙串），不进配置文件、不进仓库。
- 产物回传是白名单制，别为了省事把 `artifact_roots` 设成整个盘。
